VIStream: core code release guide

RELEASE

https://github.com/CN-MingZheLiu/vistream/releases/tag/core-code-20261014

Archive: VIStream_Core_Code_20261014.zip
Top-level directory: VIStream_Core_Code_20261014/

This is a source-only release of the core method, configurations, and evaluation
code. It does not include datasets, model checkpoints, a preinstalled environment,
compiled runtime dependencies, or precomputed prediction trajectories. Those
external assets and dependencies must be obtained or installed separately.
The source archive alone is not a self-contained inference installation.

1. Download and inspect the source

Download the archive from the release page and verify it against the checksum
published with the release. Extract it and begin with the included English docs:

  unzip VIStream_Core_Code_20261014.zip
  cd VIStream_Core_Code_20261014

  README.md
  docs/SETUP_EN.md
  docs/DATASET_LAYOUT_EN.md

The last three lines identify documentation files to read; they are not commands.

The retained source layout includes:

  source/original_project/VIStream
  source/original_project/lingbot-map

Native sources and patches are included for inspection and building, including
native_stage/vendor/native_sources.tar.gz. Compiled libraries and runtime binaries
are not supplied in this release. Consult the included manifests and license
notices for the exact retained files and third-party provenance.

2. Provision external dependencies

Follow docs/SETUP_EN.md to prepare the Python/CUDA environment, required model
checkpoints, native libraries, and other external assets. Full sensor inference
requires Linux and an NVIDIA GPU with a compatible driver. The earlier validated
runtime used Ubuntu 22.04, x86_64, glibc 2.35, NVIDIA H20-3e GPUs, driver 550.127.08,
and Torch 2.8.0+cu128. These describe that validation system; the source release
itself does not install or validate the same runtime on a new machine.

The original scripts/bootstrap.py and scripts/run_kitti.py are retained as source
for provenance and integration. They expect runtime assets omitted from this
source-only archive. Do not interpret their presence as a ready-to-run setup, and
do not bypass their asset or integrity checks to claim an equivalent reproduction.
Read the included setup guide before adapting these entry points or assembling
their required external assets. No new GPU inference validation is claimed for
this source-only distribution.

3. Supply your own KITTI data

Follow docs/DATASET_LAYOUT_EN.md for images, camera timestamps, calibration, and
raw IMU. Ground truth is used only in the independent evaluation stage, not as an
input to trajectory generation. In the recorded configuration, sequence 03 has no
matching IMU; do not zero-fill it or copy another sequence's IMU.

The code retains the original separation between fresh generation and scoring.
Recorded trajectory data in the website power an interactive replay; they are not
substitutes for new predictions from raw images and IMU.

4. Interpret the reported measurements

An earlier validation of the complete runtime, with its required checkpoints and
external assets provisioned, completed fresh inference on KITTI 00–10: all 11
sequences and 132 stages succeeded. Its mean Sim(3) ATE values were:

  LingBot-Map: 32.48667634836823 m
  VIStream, loop closure off: 15.249139177523158 m
  VIStream, loop closure on: 9.095139962136498 m

These round to 15.25 m and 9.10 m for the two VIStream conditions. They did not
exactly reproduce the earlier repaired references of 15.08083551911737 m and
10.406424994970628 m, which round to 15.08/10.41 m. The strict numerical status was
NOT_REPRODUCED. The later repaired configuration also differs from the original
paper configuration associated with the 16.52/9.53 m table.

The later repair includes whole-sequence consistency checks and is an offline
configuration. These recorded measurements do not establish that extracting the
source archive reproduces the result. Datasets, checkpoints, calibration, runtime,
sampling, native scheduling, and the exact configuration must all be accounted
for in any new experiment. Floating-point aggregation, custom bundle adjustment,
and native thread scheduling can change results even with fixed random seeds.

5. Preserve the evaluation protocol

The retained evaluation tools are in evaluation/, including verify_results.py.
The original full-run contract checks 132 stage receipts and 33 predictions
(visual, loop off, and loop on for each sequence), their hashes, source records,
and exact sampling support before ground truth is supplied to scoring.

Visual sampling uses every sixth frame and retains the final frame. Motion experts
process the full image sequence before returning the shared evaluation support.
The recorded configuration uses the benchmark_c2w pose interpretation and stores
opencv_c2w separately for inspection. Changing these choices changes the protocol.

Scoring uses positional ATE RMSE after independent Sim(3) alignment for each
trajectory, then averages the 11 sequences with equal weights. This is not an
all-frame SE(3) error. Ground-truth files must remain unchanged for hash checks.

Successful generation, sealing, and evaluation are distinct states. REPRODUCED
requires all 33 fresh results to match the references within the fixed 1e-8 m
numerical tolerance and all integrity checks to pass. NOT_REPRODUCED means that
this numerical criterion was not met. Two-decimal agreement is reported separately.
REFERENCE_RECOMPUTE_MATCH refers to recomputing cached reference predictions and
must not be presented as fresh inference. An audit type of namespace_mounts means
an isolated-mount audit, not a complete system-call trace.

Report the actual full table and run records for each new experiment. Do not select
runs, remove sequences, change sampling, or relax tolerances to manufacture a match.
The website's film and trajectory viewer replay recorded results; playback speed
is not a measurement of inference throughput.
