1. Package contents

The package includes the VIStream, LingBot-Map, DPVO, DROID, and other source code
used by this configuration; required model checkpoints; the ORB vocabulary;
camera/IMU configurations; compiled extensions; repaired native libraries; an
offline Python environment archive; and tools for generation, sealing, and
independent evaluation. Manifests and SHA256 hashes verify third-party provenance
and the retained source. Original Git metadata were removed to avoid including
sample ground truth, IMU, or depth data from repository history.

KITTI images, raw IMU, ground truth, and old prediction trajectories are excluded.
Reference scores are used only for independent comparison after generation; they
are not inputs to inference. No old trajectory.npz or candidate files are needed.

2. Runtime requirements

The validated baseline is Linux Ubuntu 22.04, x86_64, glibc 2.35, and an NVIDIA GPU.
The validation machine used H20-3e GPUs and NVIDIA driver 550.127.08; the Python
environment contains Torch 2.8.0+cu128. The host must provide an NVIDIA driver
compatible with this environment. The Python environment archive does not install
the driver. The runner verifies that the loaded Torch/CUDA computation libraries
come from the package; the CUDA driver and system ABI libraries may come from the
host. Model inference does not download network resources.

macOS can store, download, or extract the ZIP, but cannot run these Linux CUDA
binaries. Reserve at least 40 GB for the package, extracted environment, and run
outputs, in addition to dataset storage. The environment archive is approximately
6.54 GB, the extracted environment approximately 12 GB, and the main visual
checkpoint approximately 4.63 GB. Keeping both downloaded release parts and the
restored ZIP requires additional temporary disk space.

Run the following commands from the package root, replacing /path/to with your
actual directories. An earlier delivery used two independently extractable ZIP
archives; those must be extracted into the same parent directory. That earlier
two-archive format is different from this release's six .zip.partNN files, which
must first be concatenated as described above.

3. Restore the offline environment

  cd /path/to/VIStream_KITTI_Reproduction_20261012
  python3 scripts/bootstrap.py

Bootstrap verifies the environment archive, restores runtime/envs/lingbot-map,
runs conda-unpack, and fixes editable-dependency paths so inference processes load
the bundled source under /bundle in the isolated namespace.
Do not move the extracted environment after restoration. To relocate the package,
retain the old directory and run bootstrap again in a newly extracted package
directory. Normal use does not require --repair-existing; that option is intended
only for development validation.

extracted_from_archive=true in runtime/bootstrap_receipt.json records that this
restoration actually extracted the environment archive. Successful restoration
confirms installation only; the runtime preflight below is still required.

4. Prepare the data and run preflight

See docs/DATASET_LAYOUT.txt for the exact layout. Put images, camera timestamps,
and calibration in the KITTI odometry directory, and raw IMU in a separate
directory. Supply ground truth only during evaluation. Sequence 03 intentionally
has no matching IMU in this configuration: do not zero-fill it, copy another
sequence's IMU, or supply an improvised sequence-03 IMU file.

  python3 scripts/run_kitti.py \
    --kitti-root /path/to/kitti_odometry/dataset \
    --imu-root /path/to/KITTI_ODO_IMU \
    --run-root /path/to/runs/kitti_preflight_001 \
    --gpus 0 \
    --native-workers 1 \
    --preflight-only

Each --run-root must not already exist. Preflight creates its own directory, so
full inference requires another new directory. Preflight checks assets, raw image
support, required files, and environment/extension loading. IMU column definitions,
units, and camera-time alignment must still follow the dataset instructions: the
presence of a file does not establish that its contents are correct. Error records
remain in the run directory; the runner does not overwrite them or automatically
select among retries.

5. Rerun all 11 sequences from raw inputs

  python3 scripts/run_kitti.py \
    --kitti-root /path/to/kitti_odometry/dataset \
    --imu-root /path/to/KITTI_ODO_IMU \
    --run-root /path/to/runs/kitti_full_001 \
    --gpus 0 \
    --native-workers 1

The default run covers all 11 sequences, 00 through 10, with 12 stages per sequence
and 132 stage receipts in total:
visual, raw_imu, loop_geometry, translation, router, dpvo, droid, base,
orb_off, fusion_off, orb_on, fusion_on.

These are program stage names in the output directory. The runner first recomputes
visual and base-motion candidates, then uses native ORB trajectories and the final
admission rules to produce the two loop-closure conditions. Independent tasks may
run concurrently, but fusion can read only completed upstream outputs from that
same run. Missing outputs are not filled from earlier experiment directories.

Start with one GPU and --native-workers 1 to keep native ORB runs serial. Multiple
GPUs can be specified as --gpus GPU-UUID-1,GPU-UUID-2 or as distinct CUDA indices;
each GPU handles one sequence task. Increasing GPU or native-process concurrency
changes scheduling. Preserve the actual parameters and do not claim that a
different schedule guarantees identical reference values. GPU memory, CPU demand,
and runtime depend on the sequence and machine; consult the actual logs.

Subset options such as --sequences 04 are for diagnostics only. They do not obtain
full-reproduction sealing or full-table acceptance. For the complete table, omit
this option or explicitly include every sequence from 00 through 10.

This configuration preserves the benchmark_c2w pose interpretation used during
generation and separately saves opencv_c2w for inspection. Do not substitute a
different key in the reproduction entry point. Visual sampling uses every sixth
frame and retains the final frame. Motion experts process the full image sequence
and return the same evaluation support. Final admission checks R² and local scale
consistency only when the base selector chooses native DPVO poses. The thresholds
and original blending weights are fixed in the package.

A native launch failure, crash, or timeout fails the run. Full acceptance currently
permits only one explicitly defined invalid ORB candidate: after a normal native
exit and complete export, the original timestamp validator rejects non-increasing
timestamps. The runner preserves evidence of this rejection and continues through
the specified fallback. Missing libraries or empty executions are not valid
fallback cases.

6. Evaluate separately after sealing

The complete generation entry point runs seal automatically. A successful seal
creates:
  /path/to/runs/kitti_full_001/PREDICTIONS_SEALED_BEFORE_GT.json

Seal checks all 132 stage receipts, 33 visual/off/on predictions, exact sampling,
provenance records, and hashes without reading ground truth. Do not reseal an
already sealed run or alter any sealed input evidence or output files. Use the
manual command only if automatic sealing has not run and all required generation
materials are complete:

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py seal \
    --run-root /path/to/runs/kitti_full_001

After obtaining your own KITTI poses/00.txt through 10.txt, run evaluation outside
the generation namespace:

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py evaluate \
    --run-root /path/to/runs/kitti_full_001 \
    --gt-root /path/to/kitti_odometry/dataset/poses \
    --report-dir /path/to/reports/kitti_full_001

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py verify \
    --run-root /path/to/runs/kitti_full_001 \
    --report-dir /path/to/reports/kitti_full_001

Use a new report-dir. Evaluation computes positional ATE RMSE after independent
Sim(3) alignment for each trajectory, then takes an equally weighted average over
the 11 sequences. This is not an all-frame SE(3) error. The evaluator verifies
ground-truth file hashes and checks that sealed predictions remain unchanged before
and after scoring. Do not reorder, change precision, or resave the GT files.

7. Interpret the results

Successful generation, successful sealing, and completed evaluation are distinct
states. A successful evaluate command does not establish that new scores equal the
reference. Read the actual full-table scores in report-dir/EVALUATION.json and the
per-item differences and status in VERIFICATION.json.

REPRODUCED means that all 33 results from this fresh run match the references within
the fixed 1e-8 m tolerance and all integrity checks pass. NOT_REPRODUCED means that
the fresh run does not satisfy this numerical criterion; all actual scores remain
available, and the program does not automatically choose another run. The number
of matches after rounding to two decimals is reported separately from strict
tolerance matching. REFERENCE_RECOMPUTE_MATCH indicates only recomputation of
cached reference outputs; it is not fresh inference.

Successful seal/evaluate commands exit with code 0. Verify returns 3 for a numerical
mismatch or a result still requiring review. Missing stages or invalid hashes,
sampling support, or provenance return 2. An access-audit type of namespace_mounts
means an isolated-mount review, not a complete system-call trace. See
evaluation/README.txt for further details of the evaluation contract.

If a new run differs from 15.08/10.41, report its actual full table, differences,
and run records. This guide, a single-sequence test, or an environment check cannot
replace the numerical acceptance result.
