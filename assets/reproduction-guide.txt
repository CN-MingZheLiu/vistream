VIStream: KITTI reproduction guide

This web page provides instructions, not the multi-gigabyte code/model/environment archive.
Obtain the complete VIStream_KITTI_Reproduction_20261012 package separately.
It requires Linux x86_64, an NVIDIA GPU and driver, raw KITTI odometry images,
camera calibration/times, raw IMU, and external ground truth for evaluation only.
Datasets and precomputed prediction trajectories are not in the reproduction package.

After extracting the complete package:
  cd /path/to/VIStream_KITTI_Reproduction_20261012
  python3 scripts/bootstrap.py
  python3 scripts/run_kitti.py --kitti-root /path/to/kitti/dataset --imu-root /path/to/KITTI_ODO_IMU --run-root /path/to/new_run --gpus 0 --native-workers 1

Then evaluate the sealed run:
  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py evaluate --run-root /path/to/new_run --gt-root /path/to/kitti/dataset/poses --report-dir /path/to/new_report
  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py verify --run-root /path/to/new_run --report-dir /path/to/new_report

Actual full fresh validation: all 11 sequences and 132 stages completed.
Mean Sim(3) ATE: visual 32.48667634836823 m; loop off 15.249139177523158 m;
loop on 9.095139962136498 m. The earlier repaired 15.08/10.41 m result was NOT
exactly reproduced. This offline repair configuration differs from the paper cohort.
Floating-point kernels and native scheduling can change results. Report each actual
run; do not pick a run to match the reference. The browser visualization is replay,
not new model inference and not evidence of inference throughput.

VIStream KITTI 完整重推理包使用说明

本包对应2026-10-12完成的KITTI修复配置，参考结果是全11条序列的
loop-off平均ATE 15.08083551911737 m、loop-on平均ATE 10.406424994970628 m。
本包对应修复后的实验配置，和原论文表16.52/9.53的冻结配置不同。
最终准入包含整段序列的一致性检查，属于离线修复配置。
这些数字来自已完成的一次运行；本包的用途是从原始传感器重新执行同一套
模型、准入和融合流程，并记录实际得到的结果，不保证未来运行逐项相同。

固定种子也不能消除当前DPVO浮点聚合、自定义BA和原生线程调度的全部波动。
不得通过挑选多次运行、删除序列、更换采样或修改验收容差制造数值匹配。
格式测试、环境导入测试和单序列运行成功都不能替代完整11序列验证。
包的实际验证进度与结果以随包QA记录和新运行的评估报告为准。

1. 包含什么

包含本配置使用的VIStream、LingBot-Map、DPVO、DROID等源码，必需模型权重、
ORB词袋、相机/IMU配套配置、编译扩展、修复后的原生库、离线Python环境归档，
以及生成、封存和独立评分工具。第三方来源与实际保留源码使用清单和SHA256
核验；原来的Git元数据已去除，避免把仓库中的样例GT、IMU和深度数据带入包。

不包含KITTI图像、原始IMU、GT或旧预测轨迹。参考分数仅用于生成结束后的
独立对照，推理不依赖它们。无需再提供旧的trajectory.npz或candidate文件。

2. 运行环境

运行基线为Linux Ubuntu 22.04、x86_64、glibc 2.35和NVIDIA GPU。
原验证机器使用H20-3e、NVIDIA驱动550.127.08；Python环境为Torch 2.8.0+cu128。
主机必须有支持该环境的NVIDIA驱动，驱动本身不由Python环境归档安装。
运行入口检查实际加载的Torch/CUDA计算库来自包内；CUDA驱动与系统ABI库
允许来自主机。模型推理不下载网络资源。

macOS可以存放、下载或解压ZIP，不能直接运行这里的Linux CUDA二进制。
请为包、环境解压和运行输出预留至少40 GB空间，数据集空间另计。
环境归档约6.54 GB，解压环境约12 GB；主要视觉权重约4.63 GB。

以下命令均在包根目录执行，路径中的/path/to需要替换为实际目录。
若交付为两个ZIP，将两部分解压到同一父目录，得到一份完整包目录。

3. 离线恢复环境

  cd /path/to/VIStream_KITTI_Reproduction_20261012
  python3 scripts/bootstrap.py

bootstrap校验环境归档，从归档恢复runtime/envs/lingbot-map，执行conda-unpack，
并修正可编辑依赖的路径，使推理进程在隔离命名空间的/bundle内加载包内源码。
恢复完成后不要移动已经解压的环境；如需迁移包，先保留旧目录，再在新的包
解压目录重新bootstrap。正常使用不需要--repair-existing；它仅供开发验证。

runtime/bootstrap_receipt.json中的extracted_from_archive=true表示本次确实
从环境归档解压。环境恢复成功只说明安装步骤完成，还需要下面的运行预检。

4. 准备数据和预检

数据格式详见docs/DATASET_LAYOUT.txt。图像/相机时间/标定放在KITTI odometry
目录，原始IMU另放一个目录；GT只在评分时提供。03没有匹配IMU是本配置的
规定行为，不要补零、复制别的序列或自行填入03的IMU文件。

  python3 scripts/run_kitti.py \
    --kitti-root /path/to/kitti_odometry/dataset \
    --imu-root /path/to/KITTI_ODO_IMU \
    --run-root /path/to/runs/kitti_preflight_001 \
    --gpus 0 \
    --native-workers 1 \
    --preflight-only

每个--run-root必须尚不存在。预检也会建立自己的目录，因此正式推理要使用
另一个新目录。预检检查资产、原始图像支持、必需文件、环境与扩展加载等。
IMU的列定义、单位和相机时间对齐仍必须符合数据说明；文件存在不等于内容
已经正确。错误记录保留在运行目录，不自动覆盖或挑选重试。

5. 全11序列从原始输入重新推理

  python3 scripts/run_kitti.py \
    --kitti-root /path/to/kitti_odometry/dataset \
    --imu-root /path/to/KITTI_ODO_IMU \
    --run-root /path/to/runs/kitti_full_001 \
    --gpus 0 \
    --native-workers 1

默认执行00至10的全部11条序列，每条12个阶段，共132个阶段回执：
visual、raw_imu、loop_geometry、translation、router、dpvo、droid、base、
orb_off、fusion_off、orb_on、fusion_on。

这些名字是输出目录中的程序阶段名。先重新计算视觉和基础运动候选，再使用
原生ORB轨迹与最终准入规则生成两种条件的结果。允许无依赖的计算并行，但
融合只能读取同一次运行中已完成的上游结果。不会从旧实验目录补齐缺失结果。

建议以单GPU、--native-workers 1开始，保持原生ORB串行。多GPU可用
--gpus GPU-UUID-1,GPU-UUID-2，或不同的CUDA编号；每个GPU承担一个序列任务。
增加GPU或原生进程并行数会改变调度，必须保留真实运行参数，不因此声称
参考数值必然相同。显存/CPU/运行时长由序列和机器决定，以实际日志为准。

--sequences 04等子集选项仅用于诊断，不会取得完整复现封存或完整表验收。
需要全表结果时必须不指定该选项，或明确提供全部00至10。

本配置保留生成时使用的benchmark_c2w位姿解释，并另存opencv_c2w供检查；
不要在复现入口擅自改用另一个key。视觉采样为每6帧并保留末帧，运动专家
使用完整逐帧图像后返回相同评估支持。最终准入只在基础选择器采用原生DPVO
位姿时检查R²和局部尺度一致性；阈值及原混合权重随包固定。

原生启动失败、崩溃或超时会使本次运行失败。当前完整验收只允许一种明确的
无效ORB候选：原生正常退出且完整导出后，原时间戳检查拒绝非递增时间戳；
这种情况保存真实拒绝证据，再由规定回退路径继续。不得把缺库或空运行当回退。

6. 封存完成后，单独评分

完整生成入口会自动运行seal。成功后应存在：
  /path/to/runs/kitti_full_001/PREDICTIONS_SEALED_BEFORE_GT.json

seal检查132个阶段回执、33条visual/off/on预测、精确采样、来源记录和哈希，
不读取GT。不要在已有seal上重复执行seal，也不要修改封存后的任何输入证据
或输出文件。只有自动封存尚未执行且完整生成材料齐备时，才手动使用：

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py seal \
    --run-root /path/to/runs/kitti_full_001

准备用户自有的KITTI poses/00.txt至10.txt后，在生成命名空间外执行：

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py evaluate \
    --run-root /path/to/runs/kitti_full_001 \
    --gt-root /path/to/kitti_odometry/dataset/poses \
    --report-dir /path/to/reports/kitti_full_001

  runtime/envs/lingbot-map/bin/python evaluation/verify_results.py verify \
    --run-root /path/to/runs/kitti_full_001 \
    --report-dir /path/to/reports/kitti_full_001

report-dir使用一个新目录。评分采用每条轨迹独立Sim(3)对齐的位置ATE RMSE，
再对11条序列等权平均。它不是全帧SE(3)误差。评分器核对GT文件哈希，并在
评分前后检查封存预测未变；GT文件不要重排、改精度或重新保存。

7. 如何读结果

生成成功、封存成功和完成评分是三个不同的状态。evaluate返回成功不意味着
新结果等于参考结果。查看report-dir/EVALUATION.json中的实际全表分数，以及
VERIFICATION.json中的逐项差值和status。

REPRODUCED：本次fresh运行的33项结果均在固定1e-8 m容差内匹配参考值，且
完整性检查通过。NOT_REPRODUCED：实际新运行不满足这一数值条件，仍保留全部
真实分数；程序不会自动挑另一轮结果。两位小数相同的数量另行报告，不与严格
容差匹配混淆。REFERENCE_RECOMPUTE_MATCH只代表参考缓存复算，不能称新推理。

seal/evaluate成功的退出码为0；verify数值不匹配或仍待审查时返回3；缺失阶段、
哈希/支持/来源错误等返回2。访问审计类型namespace_mounts表示隔离挂载审查，
不会冒充完整系统调用追踪。更多评分合同细节见evaluation/README.txt。

如果新运行不同于15.08/10.41，应交付实际全表、差值和运行记录。不要以本说明、
单序列测试或环境测试替代数值验收结论。
